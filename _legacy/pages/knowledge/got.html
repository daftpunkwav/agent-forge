GoT：图谱思维

Graph of Thoughts（GoT）将推理过程建模为图谱结构，允许任意节点之间的信息流动和协作，突破Chain-of-Thought的线性限制。

从链到图：推理结构的进化

CoT将推理视为线性链——每个步骤依赖前一步。GoT则将其提升为图结构——推理步骤成为节点，信息可以在任意节点间流动。

这种结构的优势在于：不同的推理分支可以独立发展，然后汇聚形成更强大的综合推理。比如一个分支分析数据，另一个分支查阅资料，最后将两者结合得出答案。

核心洞察：线性推理链限制了信息流。图结构允许Agent进行更复杂的推理模式——并行探索、回溯修正、多源融合。

GoT的四种核心操作

1. Splitting（拆分）

将一个推理节点拆分为多个独立的分支，每个分支进行独立的推理。类似于"头脑风暴"——同时探索多种可能性。

2. Aggregating（聚合）

将多个分支的推理结果合并为一个。Agent使用prompt将不同分支的输出综合起来，形成更完整的结论。

3. Refining（精炼）

对已有推理节点进行改进。Agent审查之前的推理，发现错误或不足，然后生成一个更高质量的版本。

4. Backtracking（回溯）

返回到之前的推理节点，基于新信息重新推理。这允许Agent修正错误路径，而不必从头开始。

GoT vs 其他推理模式

  • vs CoT：CoT是线性链，GoT是图。GoT支持并行推理和回溯。
  • vs ReAct：ReAct交替推理和行动，GoT在推理层面做结构化组织。
  • vs ToT：ToT是GoT的特例——树形结构。GoT更通用，允许任意图拓扑。

实现示例

Python · LangChain 
from langchain.graphs import NetworkxEntityGraph

# 使用图结构管理推理状态
graph = NetworkxEntityGraph()

# 添加推理节点
graph.add_node("问题分析", "用户询问预算方案")
graph.add_node("方案A", "削减研发投入")
graph.add_node("方案B", "拓展营收渠道")
graph.add_node("综合", "方案A+B组合")

# 建立推理关系（边）
graph.add_edge("问题分析", "方案A", "leads_to")
graph.add_edge("问题分析", "方案B", "leads_to")
graph.add_edge("方案A", "综合", "aggregated_with")
graph.add_edge("方案B", "综合", "aggregated_with")

# Agent可以通过图遍历进行多路径推理
for path in graph.get_all_paths("问题分析"):
    print(f"推理路径: {' → '.join(path)}")

最佳实践

  • 控制分支数量：过多分支会指数级增加token消耗，建议每步不超过3-5个分支。
  • 明确聚合策略：告诉Agent如何合并不同分支的结果，否则聚合质量会下降。
  • 适时回溯：设置回溯触发条件，避免无意义的循环。
  • 图可视化：复杂GoT推理过程很难跟踪，实时可视化图谱状态有助于调试。
