ToT：思维树

Tree of Thoughts（ToT）将推理过程组织为树形结构，允许Agent探索多条推理路径，评估中间结果，并在必要时回溯——类似人类的"考虑多种方案再决定"。

为什么要从链到树？

CoT的线性推理有一个根本性局限：一旦走了错误的路径，后续的推理都会建立在错误之上。人类不会这样做——我们会考虑多种可能，比较优劣，然后选择最佳路径。

ToT 的核心思想是：将每个推理步骤视为一个"thought"节点，Agent可以同时探索多条路径，并对每一步进行自我评估。就像下棋时考虑多种走法，然后选择最优的一步。

核心洞察：复杂问题通常有多条可行的推理路径。ToT通过探索和评估多条路径，显著提高了解决复杂问题的准确率。

ToT框架

ToT框架包含四个关键步骤：

  1. Thought Decomposition：将问题分解为中间推理步骤。例如"写一篇文章"可以分解为：确定主题 → 列大纲 → 写开头 → 写正文 → 写结尾。
  2. Thought Generation：对每个步骤，生成多个候选thought。使用"提出5个不同的开头"这样的prompt。
  3. State Evaluation：评估每个中间thought的质量。使用0-10分评分或"好/中/差"分类。
  4. Search Algorithm：使用搜索算法遍历树。BFS（广度优先）探索更多路径，DFS（深度优先）深入单一路径，或使用beam search保留top-K路径。

搜索策略

Beam Search（束搜索）

在每个步骤保留top-K个最佳thought，然后从这些继续向下探索。这是ToT最常用的策略。

# Beam Search 伪代码
beam = [initial_thought]
for step in range(max_steps):
    candidates = []
    for thought in beam:
        # 生成下一批候选thought
        next_thoughts = llm.generate(thought, k=5)
        candidates.extend(next_thoughts)
    # 评估并保留top-K
    scored = evaluate(candidates)
    beam = sorted(scored, key=lambda x: x.score)[-K:]

BFS vs DFS

  • BFS（广度优先）：每层探索所有路径，适合需要广泛探索的问题。
  • DFS（深度优先）：深入单一路径到底，适合需要深度思考的问题。
  • Beam Search：折中方案，每层保留K个最佳路径。

推理模式对比

  • CoT：一条路径，不回头。简单高效，但容易走偏。
  • ReAct：一条路径+工具。适合需要外部信息的问题。
  • ToT：多路径+评估+剪枝。适合复杂规划问题。
  • GoT：任意图结构。最灵活，也最复杂。

最佳实践

  • 评估函数要可靠：ToT的效果严重依赖thought评估的质量。使用一致的评分标准。
  • 控制beam宽度：beam size=5通常是不错的起点。太宽增加成本，太窄失去探索价值。
  • 定义明确的终止条件：何时停止探索？达到目标分数？找到可接受答案？
  • 结合ReAct：ToT + ReAct = 多路径推理 + 工具调用，可以解决更复杂的任务。
