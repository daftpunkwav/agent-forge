评估系统

如何科学地评估Agent的表现？从人工标注到自动化评测，构建可靠的Agent评估体系。

为什么评估Agent如此困难？

传统的NLP评估使用固定数据集+准确率/F1分数。但Agent评估更加复杂：

  • 输出不确定：Agent的输出可能包含多个步骤，很难用单一指标衡量
  • 环境交互：Agent的表现取决于与环境的交互，而非静态的输入输出
  • 维度多样：准确性、效率、安全性、用户体验……需要多维度评估
  • 成本高昂：真实环境测试慢、贵，且难以复现
核心洞察：评估Agent不是"考一次试"，而是"持续监控"。需要建立多层级、多维度的评估体系。

评估框架

正确性评估

Agent是否完成了任务？最基本的评估维度。

  • End-to-End：任务完成率（最终答案是否正确）
  • Step-wise：每一步的中间结果是否正确
  • Path Efficiency：完成任务的步数是否最优

效率评估

  • Token消耗：每任务的平均token使用量
  • 延迟：完成任务的总时间
  • 工具调用次数：完成任务所需的工具调用次数
  • 循环次数：Agent Loop的执行次数

鲁棒性评估

  • 对抗测试：在模糊指令、噪声输入下的表现
  • 边界条件：极端场景下的行为
  • 错误恢复：工具调用失败后能否自我修正

评估工具

from langchain.evaluation import load_evaluator

# 1. 正确性评估
correctness_eval = load_evaluator("cot_qa")
result = correctness_eval.evaluate(
    query="2024年巴黎奥运会中国金牌数？",
    prediction="40枚",
    reference="40枚"
)
print(f"正确性: {result['score']}")

# 2. 路径评估 - 分析Agent的推理过程
path_eval = load_evaluator("trajectory")
result = path_eval.evaluate(
    agent_trajectory=[
        {"thought": "需要搜索", "action": "search"},
        {"thought": "结果不完整", "action": "search_again"},
        {"thought": "找到答案", "action": "finish"},
    ],
    reference_trajectory=[
        {"thought": "需要搜索", "action": "search"},
        {"thought": "找到答案", "action": "finish"},
    ]
)
print(f"路径效率: {result['score']}")

标准Benchmark

  • HumanEval：代码生成能力
  • GSM8K：数学推理
  • MATH：竞赛数学
  • HotpotQA：多跳问答
  • WebArena：Web导航任务
  • SWE-bench：软件工程任务
  • AgentBench：综合Agent能力

最佳实践

  • 分层评估：单元→集成→E2E，逐层评估
  • A/B对比：任何Agent改进都应该与基线对比
  • 成本跟踪：评估结果必须包含token消耗和延迟
  • 定期回归：每次模型/prompt变更后重新跑基准测试
