记忆系统

Memory 让 Agent 拥有"记住用户说过什么"的能力。从短期对话记忆到长期用户画像，记忆系统是构建个性化Agent的基础。

为什么Agent需要记忆？

LLM 本身是无状态的——每次调用都是独立的，不记得上次对话说了什么。但真实的Agent应用需要：记住用户的偏好、记住对话的上下文、记住之前做过什么。

记忆系统就是解决这个问题的方案——在LLM的上下文窗口之外，维护一个持久化的信息存储，在每次对话时按需检索和注入。

核心洞察：记忆不是简单地把所有对话存下来。好的记忆系统知道"什么重要、什么不重要、什么已经知道了、什么还需要确认"。

记忆的层次

短期记忆（对话历史）

当前对话窗口内的消息序列。受限于Context Window大小，通常只能保留最近几轮对话。

工作记忆（Working Memory）

Agent当前任务的临时状态——正在处理的问题、已尝试的方案、待确认的事项。在单个任务执行周期内有效。

长期记忆（Long-term Memory）

跨越多个对话会话的持久化信息。包括用户偏好、历史决策、学到的经验等。通常存储在向量数据库中。

记忆系统架构

Python · Agent Memory 架构 
class AgentMemory:
    """分层记忆系统"""

    def __init__(self):
        self.short_term = []      # 短期：对话历史
        self.working = {}         # 工作：当前任务状态
        self.long_term = VectorStore()  # 长期：向量数据库

    def recall(self, query: str, top_k: int = 5):
        """根据查询检索相关记忆"""
        # 1. 检索长期记忆
        long_term_results = self.long_term.search(query, top_k)

        # 2. 组合上下文
        context = {
            "recent_messages": self.short_term[-4:],
            "working_memory": self.working,
            "relevant_memories": long_term_results,
        }
        return context

    def store(self, info: str, importance: float):
        """存储新记忆"""
        embedding = embed(info)
        self.long_term.add(embedding, {
            "content": info,
            "importance": importance,
            "timestamp": now(),
        })

记忆策略

  • 重要性评分：每次存储时给记忆打分（0-1），定期清理低分记忆
  • 时间衰减：旧记忆的检索权重随时间递减
  • 语义检索：用向量相似度找到与当前查询最相关的记忆
  • 主动回忆：在关键节点（任务开始、重大决策后）主动触发记忆写入
  • 遗忘机制：明确标记"已学会"的记忆，减少重复检索
