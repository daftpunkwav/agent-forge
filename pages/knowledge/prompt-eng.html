Prompt 工程

Prompt是人与LLM交互的唯一接口。写好Prompt，是成为Agent开发者的第一道门槛。

什么是Prompt工程？

Prompt Engineering 是设计和优化输入文本，以引导LLM生成期望输出的技术。好的Prompt可以：

  • 让模型更准确地理解意图
  • 引导模型按照期望格式输出
  • 减少幻觉和错误
  • 激发模型的最佳性能
核心洞察：Prompt不是"提问"，而是"编程"——你把模型当成一个需要精确指令的执行者。

核心原则

1. 清晰具体

模糊的指令产生模糊的输出。告诉模型：具体要什么、不要什么、用什么格式。

✗ 不好

"写个Python程序"

✓ 好

"写一个Python函数，使用正则表达式验证邮箱格式，返回True/False，包含3个测试用例"

2. 结构化

使用清晰的结构组织Prompt：角色、任务、约束、示例、输出格式。

3. Few-shot示例

提供几个输入输出的示例，模型会模仿这个模式。这是最有效的Prompt技巧之一。

4. System Prompt设计

System Prompt是Agent的"灵魂"。好的System Prompt应该定义：角色、能力边界、行为规则、输出格式。

推荐模板

Agent System Prompt 模板 
你是一个专业的{ROLE}助手。

## 能力
- 你可以使用以下工具：{TOOLS}
- 每次回答前先思考用户需要什么
- 不确定时请提问，不要猜测

## 规则
- 回答简洁，避免冗余
- 代码必须有注释
- 数字和日期必须准确
- 涉及安全的内容必须谨慎

## 输出格式
- 使用 Markdown 格式
- 代码块标注语言类型
- 复杂内容使用列表

## 示例
{EXAMPLES}

进阶技巧

  • Chain-of-Thought："请一步步思考"
  • Role Prompting："你是一个资深工程师"
  • Constraint Prompting：明确列出"不要做"的事情
  • Self-Consistency：让模型多次推理，投票选出最佳答案
  • Reflexion：让模型反思自己的输出并改进

常见错误

  • Prompt太长：超过模型能力范围的prompt会被截断或忽略
  • 矛盾指令："简短回答" + "详细解释" = 模型困惑
  • 假设知识：模型不知道你的私有数据
  • 不测试边界：只在happy path下测试prompt
